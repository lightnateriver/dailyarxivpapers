摘要总结
论文指出在线策略自蒸馏（OPSD）在多轮智能体后训练中存在根本缺陷：它用特权信息（PI）构造同一模型的更强教师视角做 token 级监督，结果只教会学生“自信地行动”，却学不到支撑该行动的信息，训练后的智能体表现得仿佛掌握了自己从未观测到的特权信息，最坏情况下性能甚至低于未训练的基座模型。为此作者提出 Privileged Self-Practice（PSP），把特权信息从损失函数搬到采样器：当学生模型在某个任务上的 rollout 大多失败时，由 analyzer 模型为该任务写一段简短指令注入上下文并重新采样，再用完全不变的 GRPO 目标进行训练，特权信息始终停留在 prompt 中而绝不进入 loss。在 AppWorld 与 SWE-bench Verified、三种不同学生模型上，PSP 在每种设置下都取得最佳平均分，是唯一能稳定超越纯 GRPO 的方法，AppWorld 任务目标完成率最高提升 65%，SWE-bench Verified 解决率最高提升 61%。
核心创新点
  • 首次系统揭示多轮智能体 OPSD 的失效机制：token 级特权蒸馏让学生获得“无信息支撑的自信”，性能可低于未训练基座模型，而非简单的效果打折
  • 提出 PSP 范式，将特权信息从 loss 迁移到 sampler，用“in-context 指令 + 失败触发的重采样”替代 token 级教师监督，保持 GRPO 目标原样不动
  • 设计 analyzer 模型生成 per-task 短指令的触发式数据构造流程，仅在任务 rollout 大部分失败时介入，成本可控地补足学生缺失的信息
  • 在 AppWorld 与 SWE-bench Verified 上以三种学生模型完成交叉验证，PSP 全部取得最佳平均分，且是唯一持续优于纯 GRPO 的方法，任务目标完成率提升达 65%、解决率提升达 61%
解决的问题 / 适用场景
面向需要用强化学习后训练多轮工具调用或软件工程智能体的团队：在无法让学生模型真正获得环境状态、参考答案等特权信息的真实部署条件下，避免自蒸馏带来的“虚假自信”与性能倒退，可直接用于 Agent 后训练流水线和代码仓库自动修复（SWE Agent）服务。

未明确披露
点击收起
摘要总结
论文针对两个痛点：强化学习在采样不到正确轨迹时缺失正向正确性信号，而同策略蒸馏（OPD）又被学生同策略分布下可达的推理轨迹所限制。作者提出 CataOPD，把教师当作“催化剂”而非蒸馏目标，从而扩大可达空间，并把学生自己产出且经校验的轨迹内化进一个无催化剂的策略。方法由三部分组成：Self-Rescue Routing 把经验上全部失败的题组当作路由信号（而非教师介入触发器），先通过额外的同策略自采样自救；对自救后仍未解决的问题，Catalytic-Guided Self-Resolution 用催化引导在“引导后学生分布”中催生一条经校验的学生自身轨迹；Barrier-Weighted Internalization 以引导与无引导条件间的 log-prob 差距对 token 加权。实验表明 CataOPD 优于现有基线，能把学生的独立推理能力延伸到仍未恢复的问题上，并在无催化剂推理条件下提升分布外泛化。
核心创新点
  • 提出 CataOPD：教师仅作为催化剂使用而非优化目标，最终得到 catalyst-free 策略，推理阶段不再依赖教师，突破了 OPD 受限于学生同策略分布可达轨迹的瓶颈。
  • Self-Rescue Routing：以“经验上全失败的题组”作为路由信号而非教师介入触发器，先靠额外的同策略自采样把可自救的问题留在学生自身分布内解决。
  • Catalytic-Guided Self-Resolution + Barrier-Weighted Internalization：对自救失败的问题用催化引导诱导学生自行产出经校验的轨迹，并按引导/无引导 log-prob 差距给 token 加权，把更新聚焦在“无引导时难以产生的决定性 token”上。
  • 实验显示在无催化剂推理下既优于现有 RL/OPD 基线，又能把独立推理能力扩展到仍未恢复的问题并改善 OOD 泛化。
解决的问题 / 适用场景
适用于以 RL 或蒸馏提升 LLM 数学/逻辑推理能力的训练环节，尤其是正确轨迹难以采样、奖励或验证信号稀疏的难题场景；训练后学生可脱离教师独立部署推理，从而降低线上推理依赖与成本。

摘要总结
论文指出基于图与超图的 RAG 虽然能缓解大模型幻觉，但现有结构化 RAG 系统无论查询复杂度如何都采用静态遍历策略，作者把这一现象定义为“静态检索谬误”，认为它是简单查询计算冗余、复杂推理出现认知上下文缺口的主因。为此提出 Asymmetric Dynamic Routing（ADR），一个在层次化知识图上运行的意图条件检索框架：用轻量结构化分类器把查询动态分派给三个非对称拓扑遍历算子——局部事实锚定、自底向上邻接扩散、自顶向下洞见锚定，三者共同实现跨层次知识层的双向信息流动。在五个领域语料上的实验表明 ADR 在保持较强推理性能的同时，prompt token 消耗最多降低 48.7%、端到端查询延迟降低 45.3%，给出面向查询自适应的超图 RAG 的质量—效率折中。

未明确披露

摘要总结
论文系统考察长文档问答中 VLM 流水线的三类设计选择：如何把含图表、表格与复杂版式的文档喂给模型，只送部分页面时选哪种检索器，以及采用 agentic 还是静态流水线，并在 MMLongBench-Doc 与 LongDocURL 两个基准上同时评测前沿 API 模型与开源权重 VLM。结果显示六工具 agent（page、table、figure、search 调用）只有在回答模型足够大时才划算：Qwen3.5-4B 与 9B 下不如静态整页输入，Qwen3.5-27B 时持平，Sonnet 4.5 时领先；在 LongDocURL 上各 reader 均持平或领先，相对最强静态流水线的优势在前沿 reader 与 MMLongBench-Doc 上最明显。检索模态比具体检索器更重要——最强图像检索器胜过最强文本流水线，文本侧单个现成 cross-encoder 重排即可媲美更重的多阶段 LLM 流水线，且 top-k 图像检索在每个 reader 上最省 token，约为全页输入的七分之一到四分之一。跨三类选择看，三条最强流水线在不同问题上各有胜负，按问题挑选最佳流水线的 oracle 比最强单流水线高约 13 个点，而按证据类型路由几乎回收不到这部分收益。
核心创新点
  • 在同一实验框架下对照长文档 QA 的三类设计维度（文档输入形式、检索模态与检索器、agentic 与静态流水线），并同时覆盖 MMLongBench-Doc、LongDocURL 两个基准与前沿 API、开源权重两类 reader。
  • 给出六工具 agent（page/table/figure/search）收益随 reader 规模变化的量化规律：Qwen3.5-4B、9B 低于静态整页输入，27B 持平，Sonnet 4.5 领先。
  • 发现检索模态比检索器选择更关键：最强图像检索器优于最强文本流水线；文本侧单个 off-the-shelf cross-encoder 重排即与多阶段 LLM 流水线相当；top-k 图像检索最省 token，约为全页输入的 1/7–1/4。
  • 用逐题 oracle 选取最佳流水线相对最强单流水线约提升 13 个点，说明三条强流水线具有互补性，而 evidence-type routing 几乎无法复现该增益。
解决的问题 / 适用场景
面向企业文档智能、长 PDF/财报/论文问答等系统的技术选型与成本控制：指导在整页输入、图像或文本检索、agentic 多工具问答之间做精度—token 权衡，并提示按证据类型路由并不能自动获得多流水线互补带来的收益。

  • 给出错误证据比缺失证据危害更大的实证结论，并审计现有基准：其分数无法可靠预测因果级联敏感度，且在分布偏移下失效。
