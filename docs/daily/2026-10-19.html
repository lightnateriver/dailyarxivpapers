摘要总结
分层多智能体系统中 Leader 负责任务分派、子智能体负责执行，但由于最终答案只对子智能体给出间接反馈，联合训练十分困难，而用 LLM judge 打分又受 judge 自身评判质量制约。论文提出 MultiAgent-OPD，把同策略蒸馏（on-policy distillation）与强化学习结合，端到端联合训练共享参数的 Leader–Searcher–Answerer 团队：先用答案正确性训练一个 Searcher–Answerer 工作流中的 Teacher，团队训练阶段冻结该 Teacher 对学生自己生成的 search 与 summary token 逐 token 打分，为 Searcher 提供局部过程监督，Leader 从团队整体成功中学习、Answerer 从候选答案正确性中学习。在七个数据集上系统取得 38.68% 的 macro avg@4，分别比 Prompted Critic 高 4.06 个百分点、比已训练的级联多智能体系统 C-MAS + RL 高 2.61 个百分点，且在四次尝试内解出更多问题。
核心创新点
  • 提出 MultiAgent-OPD，用同策略蒸馏替代外部 LLM judge，把冻结 Teacher 的 token 级打分作为 Searcher 的局部过程监督，与 RL 的团队级奖励联合优化共享参数三角色
  • 设计分层信用分配：Leader 由团队最终成败驱动，Answerer 由候选答案正确性驱动，Searcher 由 Teacher 对其 search/summary token 的稠密信号驱动
  • Teacher 先在 Searcher–Answerer 工作流中以答案正确性训练，再冻结用于蒸馏，避免 judge 质量波动污染训练信号
  • 在七个数据集上以 macro avg@4 为指标取得 38.68%，相对 Prompted Critic 提升 4.06 个点、相对 C-MAS + RL 提升 2.61 个点，并提高四次尝试内的解题覆盖率
解决的问题 / 适用场景
适用于开放域检索问答、深度研究型搜索等需要 Leader 拆解问题、多个 Searcher 并行取证再汇总作答的多智能体系统，解决子智能体缺少可验证局部监督、只能靠最终答案间接学习而导致端到端训练失效的工程问题。

Distill Until Divergence: Error-Truncated Hindsight Distillation for Agentic RL
蒸馏至发散：面向智能体强化学习的错误截断式事后蒸馏
未明确披露
点击收起
摘要总结
论文针对长程交互智能体在基于结果（outcome-based）的 GRPO 训练中缺乏对中间决策细粒度指导的问题，指出现有“把完整轨迹蒸馏为可复用技能 + 事后条件 OPD”的做法存在一个关键错配：技能带来的概率偏移并不等于与奖励对齐的信用分配，尤其在某个错误动作改变了后续交互状态之后，以技能为条件的监督会与当前状态失配。为此作者提出错误截断式事后蒸馏方法，按轨迹最终成败与错误边界把两类互补的 hindsight 技能分流：Positive 技能刻画成功工作流，用于强化成功轨迹及错误发生前的决策；Negative 技能刻画失败特有的纠正方式，专门指向决定性错误。错误发生之后的轨迹后缀则完全交由 GRPO 优化，从而保留基于结果的学习，不把可能已错配的事后监督延伸过去。实验显示该方法在任务表现上具备竞争力，并支持有效的细粒度信用分配。
核心创新点
  • 提出按轨迹结果与错误边界对事后技能进行双向路由的机制：Positive 技能用于强化成功轨迹和错误前的决策，Negative 技能用于针对决定性错误，解决了技能诱导的概率偏移未必与奖励对齐的问题。
  • 设计错误截断（error-truncated）的监督范围控制：错误之后的轨迹后缀只由 GRPO 优化，不再施加以技能为条件的 OPD 监督，避免在状态已被错误动作改变后继续使用失配的 hindsight 信号。
  • 将技能蒸馏与结果驱动的强化学习在 token 级信用分配上互补结合，在长程、动态环境的多步决策中同时获得稠密监督与结果对齐性。
  • 实验验证了在保持竞争性任务表现的同时实现更有效的细粒度信用分配，说明该分流与截断策略优于不加区分地延展事后蒸馏。
解决的问题 / 适用场景
适用于需要多步决策、环境状态随动作持续变化的长程智能体强化学习训练，例如工具调用、交互式任务求解等场景；它解决的是中间步骤奖励稀疏、错误一旦发生便污染后续监督信号的训练难题。

摘要总结
论文系统研究了 ReAct 式编程智能体是否以及如何对代码进行推理：作者收集并分析 SWE-bench-Verified、SWE-bench-Pro、SWE-bench-Lite 上来自 6 种单/多智能体脚手架的 7,955 条 issue 解决轨迹，覆盖四种编程语言，归纳出 12 种代码推理形式，发现其在 66.95% 的轨迹中出现，且与更高的解决率相关、并随任务复杂度上升而增强。研究同时揭示这种推理基本处于“无引导”状态：定位阶段停留在表层症状、近似正确的补丁得不到进一步精修、issue 需求被忽视、生成的测试行为多样性有限。为此作者提出 DeskCheck 脚手架，在仓库级 issue 解决全流程中系统引导代码推理：模拟执行路径以定位根因、模拟候选补丁以精修 near-miss 方案、对照 issue 需求审计补丁、在生成测试前推理边界输入与期望输出。在 731 个 SWE-bench-Pro 实例上，DeskCheck 相比 mini-SWE-Agent 和 Claude Code 将解决率提升 6.29%–10.53%，每实例额外成本仅 0.02–0.28 美元（平均 0.14 美元）；分阶段分析显示方法级定位召回更高、定位不精确的 issue 修复成功率更高、对近似正确补丁遗漏边界情况的检出更好，精确 McNemar 检验在所有被测 LLM 上均达 p < 10^-10 显著，重复实验表明对智能体不确定性具有鲁棒性。
核心创新点
  • 基于 7,955 条真实 issue 解决轨迹和 6 种脚手架的大规模实证分析，归纳出 12 种代码推理形式，并量化其在 66.95% 轨迹中出现、与解决率正相关且随任务复杂度增强的规律。
  • 提出 DeskCheck 智能体脚手架，把代码推理拆成四个可操作阶段：模拟执行路径定位根因、模拟候选补丁精修 near-miss、对照 issue 需求审计补丁、在写测试前推理边界输入与期望输出。
  • 在 731 个 SWE-bench-Pro 实例上相较 mini-SWE-Agent 与 Claude Code 提升解决率 6.29%–10.53%，额外成本仅每实例 0.02–0.28 美元（平均 0.14 美元）。
  • 通过分阶段指标（方法级定位召回、不精确定位 issue 的修复成功率、near-miss 补丁的边界情况检出率）定位增益来源，并以精确 McNemar 检验 p < 10^-10 及重复实验证明显著性与对智能体非确定性的鲁棒性。
解决的问题 / 适用场景
面向仓库级自动化缺陷修复（SWE-bench 类 issue resolution）场景，可直接作为 ReAct 式编程智能体的外层脚手架接入现有编码 Agent；解决的是智能体在大型代码库中只改表层症状、补丁差一点却不精修、忽略 issue 需求与边界条件而导致修复失败的实际问题。

PRIME: Towards Verifiable Evidence-Grounded Reasoning in LLM Agents
PRIME：让 LLM 智能体实现可验证、有证据支撑的推理
未明确披露
点击收起
摘要总结
论文针对 LLM 智能体按组织要求核查记录（例如漏洞报告是否具备进入调查的条件）时出现的两类失败：某项必需的检查已经失败，却仍然接受了该报告；以及没有尝试其他可能仍然成立的路径，就满足于一个更弱的结论。作者提出 PRIME（Precommitted Rules for Inference from Minimal Evidence）：它在核查开始前就固定“证据路线”，规定每一个结论可以如何被证成；再由一个独立程序记录每次检查的结果，并拒绝任何结果不足以支持的结论；当现有结果只能支持较弱结论时，它还会指出哪些检查可以支撑更强的结论，或者干脆自己执行这些检查。在 480 个公共记录任务上，直接向智能体展示要求的做法在 26.7% 的任务上给出了无依据的结论，而 PRIME 一次也没有；PRIME 的指引与追加检查把“有依据结论”的平均分从仅靠拒答时的 30.1 提升到满分 59.2。
核心创新点
  • 提出 PRIME 框架：在核查前预先承诺“证据路线”（evidence routes），显式规定每个结论允许由哪些检查与证据组合来证成，把结论与证据之间的映射从模型的隐式推理变成可审计的规则
  • 设计与智能体分离的账本式判定程序：逐条记录每次检查结果，并按规则拒绝任何不被结果支持的结论，从机制上阻断“检查失败仍然接受”这一失败模式
  • 加入主动补齐证据缺口的机制：当现有结果只能支撑较弱结论时，PRIME 会指向可证成更强结论的检查，或者自己执行这些检查，避免智能体降级收尾
  • 在 480 个公共记录任务上给出量化结果：无依据结论率由 26.7% 降至 0，有依据结论平均分由拒答基线的 30.1 提升至 59.2/100
解决的问题 / 适用场景
适用于必须把结论追溯到可核查证据的合规审核类智能体，例如漏洞报告分诊、安全公告审核、内部记录对照组织规范的核查，尤其适合部署在“不得越权下结论、结论必须可复现审计”的 LLM 智能体系统中。

摘要总结

核心创新点
  • 提出以隐藏 PDDL 模型作为形式化裁判的评测协议：自然语言任务背后由 PDDL 语义裁定动作可执行性、目标达成与可解性，取代端到端成功率与 LLM 评委作为验证手段
  • 构建并发布 5 个领域的评测集，其中包含 2 个新领域，并系统组合 4 个模型、6 种提示策略与 3 种智能体架构进行受控对比
  • 发现离线与在线之间存在显著落差：最佳配置离线解出 78% 的可解任务，在线仅 40%，原因是智能体大多不检查状态就行动；对不可解任务的识别率低于 10%
  • 实证表明更重的提示与智能体策略（self-refinement、reflection、critic、搜索式提示等）token 消耗增加 5 至 22 倍却无明确收益，规划表现的方差更多来自模型而非策略或架构
解决的问题 / 适用场景
适用于规划型 LLM 智能体（任务自动化、工具调用 agent）的能力评估与选型：帮助团队在部署前判断“高成功率”究竟来自模型真实规划能力，还是来自评测口径的漏洞，并据此决定是否值得为更复杂的提示策略与智能体架构付出 token 成本。

摘要总结
论文指出，一条伴随正确答案的推理轨迹未必能为特定学生提供有效监督，因此提出 ReDiST——一个以学生自身尝试为起点的“学生条件化”轨迹构建与蒸馏框架。ReDiST 对答案正确的草稿依据给定证据进行修订，对失败草稿则借助已验证答案补充引导后修复；随后由一个冻结的、与学生能力匹配的 reader 模型在给定问题、证据和候选轨迹的条件下，用答案可恢复性和已验证答案概率对原始与编辑候选进行筛选排序。最终对选中目标做蒸馏，并用辅助答案损失平衡轨迹监督与最终答案监督；构建与选择均离线完成，推理阶段只用蒸馏后的学生模型。在问答基准上，ReDiST 相比仅答案监督、原始轨迹以及所对比的轨迹选择与改写基线，同时提升了源任务与跨基准表现。
核心创新点
  • 提出 ReDiST 框架，轨迹不是从强模型直接采样，而是从学生自身作答草稿出发：正确草稿按证据修订、错误草稿用已验证答案引导修复，使监督信号对齐目标学习者的能力水平。
  • 引入冻结的学生匹配 reader 作为筛选器，以“答案可恢复性”和“已验证答案概率”两个指标对原始与编辑候选轨迹排序，实现轨迹教学效用的显式度量。
  • 蒸馏目标同时包含轨迹损失与最终答案损失（辅助答案损失），在轨迹监督与答案监督之间做权衡，而非单纯模仿长推理链。
  • 实验发现不同监督配方下，源任务与迁移基准上的性能排序可能不一致，说明必须在跨分布条件下评估轨迹的教学效用，而不能只看源任务。
  • 构建与选择全部离线执行，推理时仅部署蒸馏后的学生模型，不增加线上开销。
解决的问题 / 适用场景
适用于希望用小参数量学生模型承担推理任务的问答/推理系统，在只有标准答案、缺少高质量推理过程标注时，用离线构建的学生适配轨迹替代昂贵的人工思维链标注。
