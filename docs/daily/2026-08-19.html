摘要总结

  • 通过学习规划层面的审慎行为避免退化为朴素长度最小化，增强策略的可泛化性
  • 在 ALFWorld、WebShop、SciWorld 上平均较 GRPO 提升 27.2%，且额外训练开销极小
解决的问题 / 适用场景
解决多轮智能体任务中成功轨迹间优势无法区分、模型仅学到任务特定行为而缺乏可泛化规划能力的问题，适用于工具调用、网页交互导航、具身任务等智能体多轮决策的强化学习训练场景。

Beyond the Trace: Coupling an Interpretable Reasoning-State Readout to Native MoE Routing
超越思维痕迹：将可解释的推理状态读取器与原生 MoE 路由耦合
未明确披露
点击收起
摘要总结
推理模型写出的文本痕迹只是其内部过程的不完整记录。本文为 MoE 推理模型提出一套两级内部状态读取方案：首先把词表规模的高维推理状态空间（J 空间）蒸馏成 64 轴语义框架 J64（从模型自身推理状态中学习），它能读出文本 trace 中看不到的过程状态，并把“推理投入量”与“问题本身带来的压力”分离开来；相比用完全相同方式聚合同一 rollout 的基线，J64 在留出集 AUC 上提升 0.096–0.135。随后仅用原生专家路由统计量重建 J64，得到低开销代理 R64：在三个模型、两个模型家族上，其逐轴中位相关达 0.69–0.86，且在 gpt-oss-20b 上保留了 J64 预测增益的 95%–100%。读取器在两个时间尺度上支撑测试时决策：对已完成的候选集合，J64 与 R64 改进单分支选择，R64 加权投票在八个设置中的七个胜过普通多数投票；在生成过程中，滚动读取窗口驱动“累积式停止-重采样”策略（其工作点仅由训练问题确定，无需验证集调参），J64 相比打乱同源样本的对照组带来 1.1–5.9 个准确率点的提升，仅依赖路由统计的 R64 代理仍保留其中 0.9–3.2 个点。最后，针对 J64 所指认机制的路由器编辑，能诱发预测中的推理行为变化，并把诊断出的“停滞”状态从数值猜测转向精确符号执行。总体而言：J64 让潜在过程状态变得可读，而原生路由让这种读取可部署、可执行。
核心创新点
  • 提出 J64：从模型自身推理状态蒸馏出的 64 轴语义框架，可读出文本 trace 不可见的潜在过程状态，并将“推理投入”与“问题固有难度/压力”解耦，AUC 较同等聚合方式基线提升 0.096–0.135。
  • 提出 R64：仅利用原生 MoE 专家路由统计量重建 J64 的低开销代理，无需额外计算即可在生产中部署，逐轴中位相关 0.69–0.86，保留 95%–100% 的预测增益。
  • 双时间尺度测试时决策：候选集层面用 J64/R64 做单分支选择与加权投票（八种设置中七种超过朴素多数投票）；生成中由滚动读取窗口驱动累积式停止-重采样策略，工作点只在训练问题上固定，避免验证集泄漏。
  • 可解释-可干预闭环验证：按 J64 指认的机制编辑路由器，能诱发预期推理行为，并将诊断出的推理停滞从数值猜测引导至精确符号执行，说明读取到的状态与真实机制存在因果对应。
  • 方法论上突破“只读文本”的局限：将模型“写出的内容”与“实际计算过程”分离，为推理监控、测试时计算分配与干预提供全新信号源。
解决的问题 / 适用场景

ORCA 是一个面向微服务故障的自动化程序修复（APR）流水线，旨在弥合遥测诊断与补丁生成之间的鸿沟。它先从成对的故障遥测与参考遥测中蒸馏出差分特征，形成故障签名，并据此定位候选代码和部署配置位置；然后由修复图智能体（Repair Graph Agents）与探索智能体（Exploration Agent）从这些位置生成 unified-diff 补丁候选；最后通过基于遥测的补丁验证器（Telemetry-Grounded Patch Verifier）对补丁的有效性、语法语义正确性、测试预言完整性与遥测回放进行分层校验。在包含 575 个案例的基准上，ORCA 的成本效益优于所有评估基线，证明运维遥测可被转化为可执行的修复上下文。
核心创新点
  • 提出故障签名蒸馏方法，将成对故障/参考遥测的差异转化为可指导修复的定位信号，实现基于遥测的面向修复的代码与部署配置定位
  • 设计修复图智能体与探索智能体协作机制，把定位到的代码与配置证据转化为受约束的 LLM 补丁生成上下文
  • 构建 Telemetry-Grounded Patch Verifier，将补丁校验拆分为有效性、语法/语义正确性、测试预言完整性、遥测回放四个独立维度，能发现仅靠 issue 或测试评估会遗漏的修复结果
  • 在 575 例微服务故障基准上系统验证了端到端流水线，成本效益显著优于现有基线
解决的问题 / 适用场景
解决微服务故障常从运维遥测入手诊断、而现有 APR 工具却依赖 issue 报告/本地代码/失败测试启动、导致诊断与修复脱节的问题。适用于微服务系统的故障自动定位与修复、SRE 与可观测性驱动的运维自动化，以及希望用遥测数据闭环驱动 LLM 补丁生成与验证的场景。
