摘要总结
论文指出，结构化数据任务中的答案正确并不足以证明 LLM 数据智能体可靠，因为智能体可能通过无效或不可复现的计算轨迹得到基准答案。作者提出 Trace Integrity，将部署可靠性定义为计算记录必须显式、可执行、符合模式、忠实反映算子、可重放、与答案一致且可审计，并通过 execution contracts 绑定用户意图、数据库模式、算子计划、假设、可执行查询、验证状态和最终答案。论文还提出 CAIT（Correct Answer / Invalid Trace）率，在 BIRD Mini-Dev 上，Direct SQL、Operation Summary + SQL 和 Contract-First SQL 的答案准确率分别为20%、22%和24%，但 Trace Integrity 通过率仅为39%、43%和40%，CAIT 率仍高达55%、59.1%和45.8%。
核心创新点
  • 提出 Trace Integrity 评估标准，从显式性、可执行性、模式有效性、算子忠实性、可重放性、答案一致性和可审计性七个方面检查答案背后的计算轨迹。
  • 识别真实部署中的 Structure Gap：自然语言推理和自由格式 rationale 无法稳定表达数据库查询所需的算子级程序。
  • 设计 execution contracts，将用户意图与 schema 元素、operator plan、假设、可执行 SQL、验证状态和最终答案链接成结构化审计工件。
  • 提出 CAIT Rate 指标，用于衡量答案正确但计算轨迹无效的静默失败；在 BIRD Mini-Dev 上，Contract-First SQL 虽达到24%答案准确率，仍有45.8%的输出属于正确答案/无效轨迹。
解决的问题 / 适用场景
适用于企业 BI、自然语言数据库查询、数据分析助手和需要合规审计的 LLM 数据代理系统。该标准可帮助系统发现查询依据不足、不可复现或与最终答案不一致的隐性计算错误，而不是只检查答案是否匹配参考结果。

摘要总结

  • 提出 ReliableRAG，据论文所述是首个通过逐三元组可靠性评估来缓解多跳问答中欺骗性错误信息的可靠性驱动框架。

  • 通过 Top-K 可靠且非冗余三元组选择机制压缩证据集合，降低单个错误片段进入后续推理链的风险。
