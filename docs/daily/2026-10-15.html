STP-GUI: Spatially-Aware Token Pruning for Efficient Web-GUI Agents
STP-GUI：面向高效 Web-GUI Agent 的空间感知 Token 剪枝
未明确披露
点击收起
摘要总结
针对 Web-GUI Agent 依靠截图 grounding 时需要处理高分辨率画面与多轮历史、产生过量视觉 token 而导致推理开销巨大的问题，论文指出现有面向自然图像的 token 剪枝方法多按重要性分数独立选点，会把识别按钮、图标、超链接等小 GUI 元素所依赖的局部视觉结构打碎。为此提出 STP-GUI，一个查询引导（query-guided）的 token 剪枝框架：在激进 token 削减下同时保留指令条件下的细粒度 token 打分，并执行空间连贯的窗口级（window-level）选择，其中轻量选择器通过策略学习优化而 VLM 主干保持冻结。在 Online-Mind2Web 上，仅保留 21% token 时仍保有全 token 性能的 77.7%，推理延迟降低 31%、FLOPs 降低 57%；在 Android in the Wild 上的结果进一步表明方法可迁移到移动 GUI 环境。
核心创新点
  • 把 GUI token 剪枝从独立打分选点改为空间连贯的窗口级（window-level）选择，避免破碎按钮、图标、超链接等小元素所需的局部视觉结构
  • 提出查询引导的 token 剪枝框架，同时保留指令条件下的细粒度 token 打分，并用策略学习（policy learning）训练轻量选择器、冻结 VLM 主干
  • 在 Online-Mind2Web 上以 21% token 保留率保住 77.7% 全 token 性能，同时降低 31% 推理延迟与 57% FLOPs
  • 在 Android in the Wild 上验证了向移动端 GUI 环境的迁移能力
解决的问题 / 适用场景
用于以截图 grounding 的 Web 与移动端 GUI Agent（浏览器自动化、界面点击操作），在低 token 预算下降低 VLM 推理成本与延迟；适用于高分辨率截图、多轮历史的高并发 GUI 操作服务场景。

AtomSearch: Evidence-Grounded Tree Search for Agent Skill Optimization
AtomSearch：面向智能体技能优化的证据锚定树搜索
未明确披露
点击收起
摘要总结
现有智能体技能优化方法要么一次性改动多条规则导致变更难以审查，要么仅以局部编辑的即时得分判断优劣而丢弃有价值的中间状态。AtomSearch 通过对比式原子编辑（Contrastive atomic editing）把每次最小规则修改与失败/成功执行、行为假设和预期作用范围绑定，再用技能状态树搜索（Skill-State Tree Search, STS）评估短编辑组合并将其保留为可回溯、可扩展的可执行状态，同时以结果记忆（Outcome memory）为后续提案提供修复与回归统计数据。作者在四个任务、五个目标模型上评测：使用 deepseek-v4-flash 时在四个任务中的三个超过 SkillOpt，其中 LiveMathematicianBench 上提升 9.68 个百分点，而 SkillOpt 的最终技能字符数是它的 2.3~19.7 倍。在 67% 的已完成搜索中，最优验证状态都经过一个在其深度上并非最高分的祖先状态。
核心创新点
  • 提出对比式原子编辑（Contrastive atomic editing）：每次只改动一条原子规则，并将该改动与失败执行、成功执行、行为假设和预期作用范围显式关联，使修改可审查且带有证据依据。
  • 设计技能状态树搜索（Skill-State Tree Search, STS）：对短编辑组合进行评估，并选择性保留为可重新访问、可继续扩展的可执行技能状态，从而支持搜索非贪心路径。
  • 引入结果记忆（Outcome memory）：将观察到的修复成功与回归统计反馈给后续编辑提案，形成闭环的搜索引导。
  • 实证发现：在四个任务、五个目标模型上，使用 deepseek-v4-flash 时三个任务优于 SkillOpt，LiveMathematicianBench 提升 9.68 个百分点；同时产出的技能更紧凑（SkillOpt 最终技能字符数为其 2.3~19.7 倍）；67% 的完成搜索中最优验证状态经由非当前深度最高分的祖先状态。
解决的问题 / 适用场景
适用于需要在冻结基座模型上通过可编辑外部指令持续改进智能体行为、且要求改动可审查、技能体积可控的工程场景，例如数学推理类基准任务与多模型（含 deepseek-v4-flash）部署下的智能体技能自动迭代与版本管理。

Harness Policy Distillation: Aligning Agent Policies with Runtime Semantics
Harness 策略蒸馏：将智能体策略与运行时语义对齐
未明确披露
点击收起
摘要总结
把通用模型部署为智能体，意味着它必须运行在特定产品运行时 harness 内，由 harness 决定哪些动作可执行、状态如何推进以及循环何时终止，而普通轨迹监督只标注采取了什么动作，把动作背后的运行时语义留在了隐含状态。Harness Policy Distillation（HPD）将这种运行时控制语义显式化为与动作并列的训练目标：它把参考轨迹回放进 harness，恢复轨迹数据中隐含的运行时语义，并在每个模型调用边界表示为控制文档（control documents）。这些文档作为特权信息供教师模型生成动作，再由 harness 验证保证目标动作在运行时契约下可执行；训练时共享模型同时在由控制状态特权信息恢复的运行时语义与原生历史上进行联合监督，从而把语义内化进策略，部署时只需原始 harness 接口、无需控制文档或额外补充。在 TRAJECT-Bench 与 Pi harness 上，Qwen3-8B 经 HPD 训练后自主任务成功率达 22.98%、运行时合规率 49.23%，未适配模型仅为 3.09% 和 19.90%。
核心创新点
  • 提出 Harness Policy Distillation（HPD）：将 harness 的运行时控制语义变为与动作并列的显式训练目标，把普通轨迹监督中隐含的“可执行性/状态推进/终止条件”信息转化为监督信号。
  • 控制文档（control documents）机制：通过在 harness 中回放参考轨迹，在每个模型调用边界恢复并显式表示运行时语义，作为教师生成动作的特权信息。
  • harness 验证驱动的目标筛选：用 runtime contract 校验教师生成的动作可执行性，保证蒸馏目标的可执行性，并联合控制状态特权信息与原生历史训练共享模型，使部署时无需控制文档即可用原始 harness 接口推理。
  • 在 TRAJECT-Bench 与 Pi harness 上用 Qwen3-8B 验证：自主任务成功率达 22.98%、运行时合规率 49.23%，相较未适配模型的 3.09% 与 19.90% 大幅提升，并表明 harness 验证过的教师动作对原生部署策略提升显著、联合控制状态监督可进一步增益。
解决的问题 / 适用场景
适用于把通用大模型落地为产品内智能体的部署场景：模型需要在特定运行时 harness 的约束下决策并遵守可执行性与终止契约，例如带严格动作白名单、状态机或循环终止规则的 Agent 产品，用于降低非法动作与运行时不合规导致的失败率。

摘要总结
针对 agentic 强化学习（RL）中自蒸馏方法层出不穷、但评测常在不同实验条件下复用已发表基线分数、缺乏同期方法间直接对比、且忽视训练稳定性与计算成本的问题，本文构建了统一对比基准：在 ALFWorld、ScienceWorld、Search-QA、WebShop 四个基准、三种模型规模上，把十种代表性自蒸馏方法与 GRPO 基线放在同一条件下直接比较。实验共完成 132 次训练、累计 12,124.4 H800 GPU 小时，并对预训练骨干与全部 11 种训练方法用 8 个 rollout 随机种子重复评测，除最终任务性能外还记录训练进度、稳定性与实测计算成本。论文得到三个关键结论：相比 GRPO 的增益范围有限、没有方法在所有设置下稳定胜出；强最终性能可能掩盖训练过程的不稳定；训练成本的增加并不必然转化为更好的性能。

摘要总结
论文研究把大模型 agentic 能力通过监督微调蒸馏到小语言模型（SLM）时的“进展停滞”问题：随着交互轨迹变长、涉及长推理-动作链与大量环境反馈，学生 agent 会陷入持续失败策略、难以取得实质进展的低效循环，作者的系统分析证明该现象在多种 SLM 与任务域中稳定出现。为此提出进展感知蒸馏 ProD（Progress-Aware Distillation），显式检测并惩罚学生生成轨迹中的停滞：把学生与教师之间的停滞差距编码为自适应 margin，用来自适应地惩罚可能进入停滞的步骤，并通过迭代应用该过程使学生 agent 逐步逼近教师行为。在 8 个 0.6B 到 8B 参数规模的 SLM 上、覆盖域内与域外基准的实验表明，ProD 显著缓解了进展停滞，并同时提升蒸馏后 SLM agent 的成功率与任务完成效率。

  • 提出 ProD，将学生与教师之间的停滞差距编码为自适应 margin，动态惩罚学生轨迹中可能导致停滞的行为
  • 通过迭代式蒸馏让学生逐步逼近教师行为，在 8 个 0.6B–8B SLM 的域内/域外基准上同时提升成功率与任务完成效率
解决的问题 / 适用场景

RM-OPD: On-Policy Distillation for Generative Reward Models
RM-OPD：面向生成式奖励模型的同策略蒸馏
未明确披露
点击收起
摘要总结
针对混合领域偏好数据强化学习（Mix-RL）训练通用生成式奖励模型（GRM）时存在的两大瓶颈——结果奖励导致的奖励稀疏、以及异构能力联合优化带来的跨域干扰（进而造成能力获取不均衡与普遍性奖励攻击），论文提出两阶段框架 RM-OPD（Reward Modeling via On-Policy Distillation），将“专家能力获取”与“能力整合”解耦。第一阶段用单领域 GRPO 微调培养领域专家教师模型，使其在孤立条件下达到各自性能上限；第二阶段通过（i）路由式同策略蒸馏，在学生模型自生成的评语上提供稠密的、带符号的 token 级监督，（ii）领域贡献重加权，按目标领域占比重新分配 token 指导权重以防止个别领域主导优化，（iii）可选的评价准则上下文蒸馏，将教师以领域特定评价标准为条件以强化 token 级监督。在多个 RM 基准和两个基座模型上，RM-OPD 持续优于原版 Mix-RL 及其他强基线，取得更优整体表现，并涌现出“学生超越教师”（teacher-surpassing）效应。
核心创新点

论文关注LLM生成代码的算法多样性这一尚不清楚的能力问题，提出了DivAlgo基准——一个由编程问题的算法多样化解法构成的大规模数据集，并配套一个轻量级相似度指标以支持大规模评测。作者在24个现代代码生成模型上实验，发现不受约束的模型生成代码多样性显著低于人类解法，仅捕获约31%的人类多样性，即便采用最优的多样化代码生成策略也只能达到约70%；虽然可以通过引导让模型按人类策略生成解，但仍无法复现人类解的多样性水平。结论指出代码生成模型在捕捉人类算法多样性方面存在本质局限，且过度接触模型生成代码会收窄程序员的算法词汇量。
