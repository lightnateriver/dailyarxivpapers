摘要总结
论文指出已有置信度估计器都只读取当前这一次推理过程（内省、token 概率打分或重采样），并主张单次推理不足以支撑可靠性判断，进而提出 XConf（eXperiential Confidence）：把置信度估计与模型自身积累的经验一起做。经验以模型自己过去的分级情节为记录，每条包含任务、模型反思、当时声明的置信度、最终结果，以及评级到达后写下的一条教训。面对新任务时，XConf 的 Recall 阶段检索相似任务且当时置信度相近的历史情节并读取其历史成功率，Reflect 阶段把该记录展示给模型，让它指出反复出现的失败模式并据此重述置信度。该方法不依赖 logit 访问或权重更新，只需一次答案生成，在推理、编码、多模态问答与交互式智能体共九个基准、三个家族四个模型上，于 24 组对比中的 23 组在区分度（AUROC）上追平或超过十次采样自洽，校准误差（ECE）更低且生成开销仅为其十分之一。
核心创新点
  • XConf（eXperiential Confidence）范式：把置信度估计建立在模型自身历史分级经验之上，而非只看当前推理过程
  • 双阶段机制：Recall 按任务相似性 + 当时声明置信度相近共同检索历史情节并直接读取历史成功率；Reflect 让模型命名自身反复失败模式后重述置信度
  • 经验记录结构：每条情节保存任务、反思、声明置信度、结果与事后教训（lesson），实现无 logit 访问、无权重更新的格式通用估计，仅需一次生成
  • 九基准四模型 24 组对比中 23 组 AUROC 追平或超过 self-consistency（10 样本），ECE 更低且成本为 1/10；用于选择性预测时，在智能体任务上弃答最低置信的 10% 可使交付成功率最高提升 8.7 个百分点
解决的问题 / 适用场景
用于需要决定哪些输出直接交付、哪些升级人工、哪些重试的可信部署场景，例如智能体任务的在线选择性预测与弃答、编码/多模态问答系统的风险分流，可在无 logit 权限、无法微调的闭源模型接口上直接落地。

摘要总结
论文针对大型推理模型（LRM）生成长思维链造成的推理开销问题，指出现有剪枝方法用模型自身 rollout 做校准却对所有推理 token 一视同仁，导致按统计显著性而非对正确推理的贡献来保护权重，错误计算背后的权重与正确计算背后的权重同样被保留，进而带来精度下降与推理链变长。作者提出 Outcome-Based Calibration for Large Reasoning Model Pruning（OBC-Prune）：先从模型回答不一致的问题中构造难度匹配的正确/错误 rollout 对，再通过干预式分析估计每句推理的因果重要性（移除其影响后对后续预测的作用），最后把因果重要性分数转成逐 token 权重，用于重新缩放 SparseGPT、Wanda、ALPS 等一次性剪枝方法的校准激活，且不修改剪枝算法本身。在 DeepSeek-R1-Distill-Qwen 1.5B/7B/14B 上以 40% 与 50% 稀疏度、在 MATH500、LiveCodeBench、AIME 2025 上评测，多数模型规模与稀疏度组合下均一致优于当前最优校准基线。
核心创新点
  • 提出 OBC-Prune 校准框架：从模型回答不一致的问题中构造难度匹配的正确/错误 rollout 对，把“结果正确性”引入校准信号，而非沿用统一对待所有推理 token 的做法。
  • 用干预式分析（intervention-based analysis）估计每句推理的因果重要性，量化移除该句影响后对后续预测的改变，把因果分数转为逐 token 权重来缩放校准激活。
  • 设计为即插即用：不修改剪枝算法本身，可直接作用于 SparseGPT、Wanda、ALPS 等一次性剪枝方法的校准激活。
  • 在 DeepSeek-R1-Distill-Qwen 1.5B/7B/14B、40%/50% 稀疏度下于 MATH500、LiveCodeBench、AIME 2025 一致超越 SOTA 校准基线，证明保留因果关键的推理回路比均匀保留观测激活更有效。
解决的问题 / 适用场景
适用于在有限显存或延迟预算下部署 DeepSeek-R1 类长思维链推理模型的场景，例如需要压缩模型体积的推理服务、边缘或私有化部署；帮助在压缩后仍保持数学与代码推理精度，并抑制剪枝导致的推理链无谓变长。

摘要总结
该研究针对此前未被探索的“语言偏见”问题，量化输入提示词所用的自然语言如何影响 LLM 代码生成性能，并评估一种缓解策略。方法上，将 AtCoder、LeetCode、BigCodeBench 三个数据集中的每道题分别以英语、日语、中文三种语言呈现，用 Accuracy（生成代码通过全部测试用例的题目数）作为指标，评测 GPT-4o、o3-mini、DeepSeek-V3.2、Llama-3、Qwen2.5-Coder-14B、Qwen2.5-Coder-0.5B 与 GitHub Copilot 共 7 个模型。结果显示各数据集官方支持语言的中位 Accuracy 最高，将题面翻译为英语可提升 Accuracy，但提升幅度在不同数据集和模型类型间并不一致。作者还发现 AtCoder 中叙述式（narrative-style）题面占比和题面长度明显更高，题面叙事性与上下文长度是语言偏见及翻译有效性的重要相关因素。
核心创新点
  • 首次系统量化 LLM 代码生成中的“提示词语言偏见”：同一批题目在 AtCoder、LeetCode、BigCodeBench 上分别以英/日/中三语呈现，在 7 个 LLM 上以 Accuracy 横向对比，隔离出自然语言本身对代码生成正确率的因果影响。
  • 把“题面机器翻译”作为一种缓解语言偏见的策略进行前后对照实验，证明翻译能提升 Accuracy 但收益依赖数据集与模型类型，并非普适有效。
  • 发现题面风格与长度是关键调节因素：AtCoder 数据集含有异常高比例的叙述式题面和更长的题面，作者据此指出题面的叙事性与上下文长度与语言偏见强度及翻译缓解效果直接相关。
  • 覆盖从闭源前沿模型（GPT-4o、o3-mini、GitHub Copilot）到开源小模型（Qwen2.5-Coder-0.5B）的跨度，表明语言偏见在模型规模/形态之间普遍存在。
解决的问题 / 适用场景
为多语言环境下的开发者与代码助手产品提供实践依据：日本、中国等非英语团队的成员在向 GitHub Copilot 或自研代码生成模型提交题面时，是否需要先把题目翻译成英语、以及在哪些数据集或任务类型上翻译才真正划算。同时也提示代码生成评测基准的设计者，题面语言与叙事风格会系统性影响模型得分，需在基准中控制该变量。

摘要总结
论文提出 MSR（Multiple Subject Reference），一种面向 LTX 视频生成的槽位感知（slot-aware）条件注入方案，解决多张参考图条件下既要保持外观、又要让每个参考对应其预定角色的问题。方法把每张参考图独立编码为一个静态 clip 并构成独立的 latent token 组，用紧凑的 Fourier 特征 MLP 注入数值槽位嵌入，再以槽位相关的时间偏移改写该组的 RoPE 旋转坐标；参考组被前置到含噪目标 token 之前，在 target-only flow-matching 训练中充当干净上下文，实现上仅用低秩适配（LoRA）并开源权重与推理流程。定性结果显示可在写实与风格化场景中生成包含不同角色与被引用环境的组合，相比早期连续参考基线参考混淆明显减少，但相似服装、复杂衣物与视角变化仍是难点。附录中的音频参考实验在视觉参数冻结的前提下加入了声音条件。
核心创新点
