未明确披露
点击收起
摘要总结
论文提出“空承诺”（empty commitment）这一失败模式：智能体承诺在当前轮次之后执行某动作，但其工具与运行时都无法兑现，且这种空洞性单从智能体配置即可判定，无需像已违约那样依赖后续轨迹。作者在承诺语义之上形式化定义空承诺，给出三类失败类型划分、面向“工具本可实现之承诺”的锚定条件（anchoring condition）以及响应级结果分类法，并提出一套测量协议：后续追问在五种依次只增加一项持久化能力（persistence affordance）的设置下运行，环境状态或隐式或显式声明。
核心创新点
  • 首次形式化“空承诺”这一独立失败模式，明确其与普通违约（broken promise）的本质区别：空洞性由智能体配置本身决定，无需观察后续轨迹即可判定
  • 在承诺语义之上给出三类失败类型、用于判断承诺是否落在工具可实现范围内的锚定条件（anchoring condition），以及响应级结果分类法（response-level outcome taxonomy）
  • 设计逐级递进的测量协议：五个设置中每一级只增加一种持久化能力（persistence affordance），并对比环境状态隐式声明与显式声明两种条件
解决的问题 / 适用场景
适用于带工具调用、定时提醒或后台任务能力的中文对话式智能体与 agent 运行时，用于在设计与评测阶段检出“我明天提醒你”这类系统根本做不到的承诺，避免用户对产品能力形成错误预期。

点击收起
摘要总结
论文揭示闭环决策智能体调试中的“验证器泄露答案”问题：若验证器的探针或谓词编码了目标身份，求解器之间的比较就会变得空洞——精确优化器看似有效，实则未消除任何真实歧义。作者在聚合轨迹调试器（aggregate-trace debugger）上复现该失败：精确最小命中集（MHS）与传播感知贪心法在 12/12 个开发用例上给出相同支撑集、在 9/12 上恢复出相同植入故障，进一步审计发现 exact-anchor 谓词在 9/9 用例中直接产生了植入对。删除这些锚点后整体植入对恢复率降至 8/9，但 hard-probe 单例对仍 9/9 命中植入对，且 0/9 用例在传播后保留了非空残余冲突族。作者据此提出以“支撑门控验证契约”（support-gated verification contract）取代求解器优先的评估流程：干净参考图须先显示重复的组件暴露，匹配的参考/当前门须建立可比的运行时证据，之后才允许经独立校准的信号规则返回检测。在含 1,440 个用例、21,600 行分区数据的预注册留出集上，72 个 regime-component 单元中 55 个通过参考门、其中 54 个通过运行时门，稳定误纳率为 0/20 且单侧精确 95% 上界为 0.1391；在被纳单元内，受影响干净流量比名义故障单元占比更能预测检测。
核心创新点
  • 发现并量化“验证器泄露答案”这一失败机制：exact-anchor 谓词在 9/9 用例中直接给出植入对，使精确 MHS 与传播感知贪心法结论完全一致，导致求解器比较失去意义
  • 提出“支撑门控验证契约”（support-gated verification contract）：参考图先证重复组件暴露 → 参考/当前匹配门建立可比运行时证据 → 独立校准信号规则方可返回检测，将证据资格与非泄露性检查置于组件选择器优化之前
  • 在 1,440 用例 / 21,600 分区行的预注册留出集上完成验证：55/72 通过参考门、54/55 通过运行时门，稳定误纳 0/20 且单侧精确 95% 上界 0.1391
  • 实验发现在被纳单元内受影响干净流量比名义故障单元占比更能预测检测，说明有诊断价值的证据来自真实受扰流量而非故障单元的名义规模
解决的问题 / 适用场景
适用于为智能体与闭环决策系统构建自动调试/故障定位工具的场景，提醒团队在调优组件选择算法前先检验验证证据是否已泄露答案，避免“更强的求解器只是认证了更强的验证器伪影”这一伪进展。

摘要总结

核心创新点
  • 将 rubric 从单纯的奖励信号扩展为三重用途：既驱动在线数据选择，又为 on-policy 自蒸馏教师提供特权上下文，还用于引导 rollout 生成方向，形成 RISED 框架。
  • 设计基于跨环境共享 rubric 词表的行为画像机制：LLM judge 为每条 rollout 打标，据画像选择与混合环境批次整体行为构成一致、且与已选数据重叠最小的样本，从而显式建模环境间的 rollout 关系。
  • 利用正面 rubric 提供 token 级额外监督、负面 rubric 引导生成远离反复失败模式，缓解全失败与全成功 rollout 组缺少组内相对奖励对比的问题。
  • 在多个模型骨干上跨环境平均 pass rate 最高，且在每一个单独环境中均排名第一或第二，并可用基于 rubric 的分析刻画性能提升伴随的行为变化。

核心创新点
  • 提出一套系统检验协议：对 6 个生物推理模型在 DNA/蛋白质/单细胞任务上做单输入扰动、跨样本证据冲突构造与线性探针分析，并对照推理链与生物输入，判断模型是否真正使用生物输入。

  • 证明表示层信息与任务表现脱钩：线性探针可在 Evo2/ESM3 表示上预测任务目标，说明基础模型编码了相关信息，但未转化为 BioReason/BioReason-Pro 的整体性能提升；而 ChatNT、Prot2Text-V2、CellWhisperer 确实依赖基础模型输入，Cell2Sentence-Scale 依赖基因句子中的差异表达基因。

论文针对编码智能体在需求欠明确时凭自身假设默默补全、生成"看似正确但行为并非用户本意"代码的问题，指出过早或过多的澄清提问会打断开发者，而现有方法难以区分哪些提问才真正关键。为此提出免训练方法 CONTRA，它先大规模生成候选澄清问题，用语义过滤剔除与所需行为无关或已被需求覆盖的问题，再对每个剩余问题分别在两种可能的回答条件下各生成程序，通过它们在共享输入上是否产生稳定的行为差异来判定该问题是否合格，最后结合交互历史决定继续提问还是停止。在 ClarifyCodeBench 上，CONTRA 在全部四个编码智能体上取得最高 F1，比最优基线的宏平均 F1 高出 13.88 个百分点；在相同 LLM 与评测协议下，其澄清召回率与 F1 也超过 Claude Code 与 OpenHands 两个编码框架。作者还把 CONTRA 实现为 Claude Code 插件，将选择性澄清嵌入日常开发流程。
核心创新点
  • 提出免训练的"广发现+双重筛选"澄清框架 CONTRA：先广撒网生成候选问题，再用语义过滤剔除与必需行为无关或已被需求解答的问题，避免遗漏与冗余提问
  • 设计基于执行行为差异的问题合格性判定：对每个候选问题在两种可能回答下分别生成程序，检查其在共享输入上是否存在稳定的行为差异，只有会改变生成行为的问题才被保留
  • 利用交互历史在已合格问题间做选择或触发停止提问的决策机制，兼顾澄清收益与对开发者造成的打断成本
  • 构建 ClarifyCodeBench 评测基准并给出全面实验：CONTRA 在四个编码智能体上均为最高 F1，宏平均 F1 较最优基线提升 13.88 个百分点，且澄清召回率与 F1 均优于 Claude Code 和 OpenHands 框架，并落地为 Claude Code 插件
解决的问题 / 适用场景
用于编码智能体在需求描述不完整时的交互式澄清决策，避免其凭假设默默实现错误行为、后续返工成本攀升，同时抑制打扰开发者的无谓提问。适用于集成在 Claude Code 类开发框架与日常软件开发流程中，按需向开发者提出少量真正影响实现行为的关键问题。
